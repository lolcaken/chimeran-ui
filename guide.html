Documentation · v0.2.0

Build a panel that lives on somebody else’s page.

ChimeraUI is 37 components and 65 icons in plain CSS, one optional behaviour file, and a fixed panel width. It is scoped so it cannot restyle the host, and it is small enough to ship inside a userscript with a single @require.

Install Live example Source

01Install

There are two ways in. A userscript should take the bundle: it carries the stylesheet, the icon set and the behaviour file in one request. A plain page can link the CSS and skip the JavaScript entirely.

Userscript — one @require

userscript header
// ==UserScript==
// @name         My Panel
// @namespace    me
// @version      1.0.0
// @match        *://example.com/*
// @require      https://cdn.jsdelivr.net/gh/lolcaken/chimeran-ui@v0.2.0/dist/chimeraui.js
// @grant        none
// ==/UserScript==

The bundle exposes window.ChimeraUI with the CSS string attached, so mount() never needs a second request.

Plain stylesheet

html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/lolcaken/chimeran-ui@v0.2.0/css/chimera-ui.css">
<body class="n1-root"> ... </body>

Without the behaviour file you write your own handlers. Every component is markup first; the CSS never depends on JavaScript.

From source

bash
git clone https://github.com/lolcaken/chimeran-ui
cd chimeran-ui
npm install        # playwright, for the overflow gate
node build.mjs     # -> dist/chimeraui.css, dist/chimeraui.js
npm test           # 41 pages at 320 / 458 / 1280 px
No runtime dependenciesThe bundle is plain CSS plus one IIFE. Nothing is fetched after the initial request, and nothing touches the host page.

02Setup

mount() creates a fixed host, attaches a shadow root, injects the stylesheet and markup, appends it to the page, and wires every behaviour. It returns the host and the shadow root.

  1. Write the panel markup. One root #n1-panel, a head, a tab rail, a main region, and one pane per tab.
  2. Load the bundle. Either the @require above or <script src="dist/chimeraui.js">.
  3. Call mount(). Pass the markup, the title and the subtitle. Everything else has a default.
  4. Listen for events. cn:change, cn:tab, cn:open and cn:close bubble out of the shadow root.
js
const PANEL = `
<div id="n1-panel">
  <div class="n1-head">
    <div class="n1-title">ChimeraUI<span class="n1-sub">0.2.0</span></div>
    <div class="n1-actions">
      <button class="n1-icon n1-close" aria-label="close">
        <span class="n1-ic" data-cn-icon="x"></span>
      </button>
    </div>
  </div>
  <div class="n1-tabs" data-cn="tabs" role="tablist">
    <button class="n1-tab" role="tab" aria-selected="true" data-cn-tab="main">
      <span class="n1-ic" data-cn-icon="home"></span><span>Main</span>
    </button>
  </div>
  <div class="n1-main"><div class="n1-main-inner"><div class="n1-stage">
    <div class="n1-pane" data-cn-pane="main">
      <button class="n1-toggle on" data-cn="toggle">
        <span class="n1-label">Enabled</span>
        <span class="n1-track"><span class="n1-knob"></span></span>
      </button>
    </div>
  </div></div></div>
</div>`;

const { host, root } = ChimeraUI.mount({
  html: PANEL,
  title: 'My Panel',
  subtitle: 'v1.0.0 · userscript',
});

Rename the panel later without re-mounting:

js
ChimeraUI.title(root, 'Page Tools', 'v1.2 · nightly');
// subtitle is optional; pass '' to remove the line
ChimeraUI.title(root, 'Page Tools');
ChimeraUI.title(root, 'Page Tools', '');
The host starts invisible to the pagemount() uses pointer-events:none on the host and re-enables it on the panel. Clicks pass through everywhere else. Give the panel a close action if the page needs its corners back.

03Prefix & scope

Every class in the kit starts with n1-. The prefix is the namespace contract: a userscript shares a document with an application it does not control, so class names have to be specific enough that no host rule collides with them.

PrefixOwnerRule
n1-LibraryStable. Safe to target from your script.
cu-Demo pagesLocal to this repository. Never used by components.
gd-This guideDocumentation chrome only.

Component selectors are also scoped under .n1-root, so the stylesheet can be linked into a page without touching body, html or bare elements. Inside a shadow root the scoping is automatic; the outer .n1-root wrapper makes the same file safe in light DOM.

html — both environments
<!-- light DOM: one wrapper class does the scoping -->
<link rel="stylesheet" href="css/chimera-ui.css">
<div class="n1-root"> ...panel... </div>

<!-- shadow DOM: mount() wraps the markup for you -->
ChimeraUI.mount({ html: PANEL });
One stylesheet per pageLoading chimera-ui.css twice doubles every rule. The bundle already carries it; do not also link it when using @require.

04Panel structure

The panel is a fixed-width column. The head and the tab rail never scroll; the active pane does. That keeps the close control reachable and stops a long list from pushing the panel past the viewport.

PartClassMetric
Panel#n1-panel458 px · radius 20 · max-height:calc(100vh - 18px)
Head.n1-headDrag handle · title + action cluster
Rail.n1-tabs31 px pills · no wrap · wheel/drag scroll
Pane.n1-pane410 px · 4 px scrollbar · overscroll-behavior:contain
Row.n1-el42 px · radius 11 · label left, value right
html — skeleton
<div id="n1-panel">
  <div class="n1-head">...title + actions...</div>
  <div class="n1-tabs" data-cn="tabs" role="tablist">...tabs...</div>
  <div class="n1-main">
    <div class="n1-main-inner">
      <div class="n1-stage">
        <div class="n1-pane" data-cn-pane="main">...content...</div>
      </div>
      <div class="n1-fade"></div>
    </div>
  </div>
</div>

The head is draggable by default: the behaviour binds pointer events to .n1-head and ignores buttons inside it. Position is not persisted; store it yourself if the panel should remember where it was.

05Tabs

A tab is a button with a role, its own icon, and its own label. The rail distributes the available width across the tabs; once they no longer fit, it stops shrinking them and becomes a scroll rail instead. Wheel, trackpad and grab-drag all move it, and a trailing click after a drag is swallowed so the rail never selects the wrong tab.

html
<div class="n1-tabs" data-cn="tabs" role="tablist" aria-label="Sections">
  <button class="n1-tab" role="tab" aria-selected="true" data-cn-tab="home">
    <span class="n1-ic" data-cn-icon="home"></span><span>Home</span>
  </button>
  <button class="n1-tab" role="tab" data-cn-tab="logs" data-cn-sep>
    <span class="n1-ic" data-cn-icon="terminal"></span><span>Logs</span>
  </button>
</div>
AttributeEffect
data-cn-tab="id"Pairs the tab with [data-cn-pane="id"].
data-cn-sepInserts a divider before this tab.
style="--tab-accent:#f0a83c"Changes the active glyph colour for this tab only.
aria-controls="pane-id"Optional; also resolves the pane when ids differ.

Keyboard: Left/Right moves between tabs, Home/End jumps to the ends. The selected tab receives focus, so the tablist is one stop in the page tab order.

08Dropdown

The custom select is a 42 px trigger plus a floating listbox. The list is placed with fixed coordinates, so it escapes a clipped scroll pane, and it flips above the trigger when there is not enough room below. Rows carry a check on the selected value.

html
<div class="n1-dd" data-cn="select" data-value="high">
  <input type="hidden" name="quality" value="high">
  <button class="n1-dd-btn" type="button" aria-haspopup="listbox" aria-expanded="false">
    <span class="n1-label">Quality</span>
    <span class="n1-dd-value">
      <span>High</span>
      <span class="n1-dd-chev" data-cn-icon="chevron-down"></span>
    </span>
  </button>
  <div class="n1-dd-menu" role="listbox" aria-label="Quality" hidden>
    <button class="n1-dd-item" role="option" aria-selected="true" data-value="high">
      <span>High</span><span class="n1-dd-check" data-cn-icon="check"></span>
    </button>
    <button class="n1-dd-item" role="option" aria-selected="false" data-value="low">
      <span>Low</span><span class="n1-dd-check" data-cn-icon="check"></span>
    </button>
  </div>
</div>

The picked value is written to data-value, to the hidden input, and to the visible label. The component emits cn:change with { value, label }. Keyboard: arrows move the active row, Enter/Space selects, Escape closes, Tab closes the list.

Native select is still thereUse .n1-select when you want zero JavaScript. The custom dropdown exists for the animated surface and the check column.

09Cards

A card groups rows under an uppercase head. The head is a button, the chevron turns with the state, and aria-expanded is kept in sync by the behaviour. This is the collapsible group used for Players, World and similar blocks.

html
<div class="n1-card">
  <button class="n1-card-head" type="button">
    Players
    <span class="n1-ic" data-cn-icon="chevron"></span>
  </button>
  <div class="n1-card-body">
    <button class="n1-toggle on" data-cn="toggle">
      <span class="n1-label">Show names</span>
      <span class="n1-track"><span class="n1-knob"></span></span>
    </button>
  </div>
</div>

Add collapsed to start shut. The body is display-toggled, so a collapsed card contributes only its head to the scroll height.

10Overlays

Modal, drawer and toast share one contract. A trigger carries data-cn-open="modal" or "drawer"; anything inside the overlay with data-cn-close closes it; Escape and a scrim click close the modal. Both surfaces animate in and out — the node stays mounted for the exit animation and is hidden after it finishes.

html — modal + drawer + toast
<button class="n1-el" data-cn-open="modal">Open dialog</button>
<div class="n1-modal" hidden>
  <div class="n1-dialog" role="dialog" aria-modal="true">
    <div class="n1-dialog-title">Clear data?</div>
    <div class="n1-dialog-body">This cannot be undone.</div>
    <div class="n1-dialog-actions">
      <button class="n1-dialog-btn" data-cn-close>Cancel</button>
      <button class="n1-dialog-btn danger" data-cn-close>Clear</button>
    </div>
  </div>
</div>

<button class="n1-el" data-cn-open="drawer">Open drawer</button>
<div class="n1-drawer" hidden>...head, body, foot...</div>

<button class="n1-el" data-cn-toast="Saved" data-cn-title="Saved"
        data-cn-msg="Written to storage.">Fire a toast</button>

Events

cn:change (toggle, slider, stepper, chips, dropdown, keybind), cn:tab, cn:open, cn:close. All bubble, so one listener on the panel root catches everything.

  console.log(e.target, e.detail);
});

13Build & test

The repository keeps source in css/ and js/, and the generated single files in dist/. build.mjs reads the import list from css/chimera-ui.css, so the aggregate file is the only order to maintain.

bash
node build.mjs       # minify + concatenate -> dist/chimeraui.css / .js
npm test             # overflow gate: 41 pages × 3 widths
git tag v0.2.0       # release snapshot for the CDN

Publishing the docs

  1. Push to main. The guide, demo, element pages and example are all static files at the repository root.
  2. Settings → Pages. Source: Deploy from a branch, branch main, folder / (root).
  3. Wait for the build. The site lands at https://lolcaken.github.io/chimeran-ui/.
  4. Tag a release. jsDelivr resolves @v0.2.0 from the tag, so pinned @require URLs stay reproducible.
Bump both versionspackage.json and the @version in build.mjs move together. The CDN path is pinned to the tag, not to main.

14Accessibility

  • Tabs use role="tab" with roving tabindex and aria-selected; panes are the matching regions.
  • Toggles expose aria-pressed; dropdowns expose aria-haspopup, aria-expanded and role="option" with aria-selected.
  • Dialogs set aria-modal, move focus in, and close on Escape and scrim click.
  • Every interactive control has a visible :focus-visible ring; programmatic focus does not draw a phantom outline.
  • prefers-reduced-motion: reduce disables every animation and transition in the kit.
  • Colour is never the only signal: badges carry text, alerts carry a heading, the dropdown marks selection with a check.
The gate runs on every pagenpm test fails on horizontal document overflow and on any block that escapes the content column, at 320, 458 and 1280 px.
